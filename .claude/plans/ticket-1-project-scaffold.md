# Feature: TICKET-1 — Project Scaffold + Core Data Model

The following plan should be complete, but it's important to validate documentation and task sanity before implementing — this is the first ticket in a brand-new repo, so there is no existing codebase pattern to cross-check against, only the architecture doc and CLAUDE.md.

## Feature Description

Stand up the foundational Next.js application: initialize the project with TypeScript and Tailwind CSS, connect Prisma to a Supabase-hosted Postgres database, define the `QuizResponse` data model, and establish the `app/`, `lib/`, `prisma/` layout that every later ticket (quiz content, quiz UI, persistence, email, checkout) builds on top of.

## User Story

As the project owner
I want a working, connected Next.js + Prisma + Supabase foundation
So that every subsequent quiz feature has a real place to plug into, instead of being blocked on infrastructure decisions

## Problem Statement

There is no code in this repository yet — only planning docs (PRD, architecture, CLAUDE.md) and AI-layer scaffolding. Nothing can be built, tested, or demoed until a real Next.js app exists and can talk to a real database.

## Solution Statement

Use `create-next-app` to scaffold a standard Next.js App Router + TypeScript + Tailwind project, then add Prisma configured against Supabase's connection-pooled Postgres (per Supabase's own Prisma integration guide), with a single `QuizResponse` model matching the architecture doc's data model. A Prisma client singleton in `lib/db.ts` avoids connection exhaustion during local development. Nothing beyond this foundation is built here.

## Out of Scope / Non-Goals

- Not included: quiz questions, scoring logic, or any `lib/quiz/*` files — that's TICKET-2.
- Not included: any UI beyond the default placeholder page `create-next-app` generates — that's TICKET-3.
- Not included: the `Order` model, Stripe, or Resend — both blocked/deferred per the PRD and ticket breakdown.
- Not changing: nothing exists yet to change; this is pure creation.

### Relevant External Documentation — READ BEFORE IMPLEMENTING

- [Supabase × Prisma integration guide](https://supabase.com/docs/guides/database/prisma) — the canonical setup: use the **connection pooler** (port 6543, `pgbouncer=true`) for `DATABASE_URL` (what Prisma Client uses at runtime) and the **direct connection** (port 5432) for `DIRECT_URL` (what Prisma Migrate/CLI uses). Why: getting this backwards is the single most common Prisma+Supabase failure mode — migrations silently fail or runtime queries exhaust connections.
- [Supabase Prisma troubleshooting guide](https://supabase.com/docs/guides/database/prisma/prisma-troubleshooting) — reference if migration or connection errors come up during Phase 2.
- [Tailwind CSS official Next.js install guide](https://tailwindcss.com/docs/guides/nextjs) — as of this research, `create-next-app@latest --tailwind` still installs **Tailwind v3.4.x by default**, not v4, despite v4 being the current stable release. Why: don't "fix" this by manually upgrading to v4 — v4's CSS-first `@theme` config is a real behavior change with no decided reason to take on here; accept whatever `create-next-app` gives by default, since matching the tool's own well-documented path is lower-risk for a project with no existing Tailwind config to preserve either way.
- [Next.js `create-next-app` reference](https://nextjs.org/docs/app/api-reference/cli/create-next-app) — exact flags to use in Phase 1.

### Patterns to Follow

No existing codebase patterns yet — this ticket **establishes** the patterns later tickets will mirror. The only binding constraints are CLAUDE.md's already-decided rules:

**Types:** `QuizResponse`'s TypeScript type must come from Prisma's generated client — never hand-write a parallel `interface QuizResponse`.

**Errors:** per CLAUDE.md's "fail loudly, never swallow" — the Prisma client singleton and any startup DB check should throw visibly on a bad connection string, not fail silently.

**Secrets:** `DATABASE_URL` and `DIRECT_URL` are server-only env vars — never imported into a `"use client"` file.

## STEP-BY-STEP TASKS

### CREATE Next.js app

- **IMPLEMENT**: `npx create-next-app@latest . --typescript --tailwind --eslint --app --no-src-dir --import-alias "@/*"` (run in the current directory, which already has non-code files in it — `create-next-app` will prompt about the non-empty directory; confirm to proceed).
- **GOTCHA**: This directory already contains `.claude/`, `.agents/`, `.archon/`, `.git/`, `CLAUDE.md`, `.mcp.json`, planning docs, and `docs/`. `create-next-app` may refuse to run in a non-empty directory depending on version — if it refuses outright rather than prompting, scaffold into a temp directory and move the generated files in, preserving everything already there.
- **VALIDATE**: `npm run dev` boots without errors; the default Next.js starter page loads at `localhost:3000`.
- **SATISFIES**: TICKET-1 AC — "`next dev` boots a placeholder page."

### CREATE `prisma/schema.prisma`

- **IMPLEMENT**: `npx prisma init --datasource-provider postgresql`, then edit the generated file's `datasource db` block to:
  ```
  datasource db {
    provider  = "postgresql"
    url       = env("DATABASE_URL")
    directUrl = env("DIRECT_URL")
  }
  ```
  Add:
  ```
  model QuizResponse {
    id        String   @id @default(cuid())
    email     String
    gender    String
    answers   Json
    skinType  String
    createdAt DateTime @default(now())
  }
  ```
- **PATTERN**: Field list and "write once, on completion" semantics from `ayurvedic-skin-quiz.architecture.md` › Data model, and `.claude/references/quiz-content.md`.
- **IMPORTS**: n/a (schema file, not TS)
- **GOTCHA**: Do not add a partial-session/in-progress table — that was a deliberate simplicity trade-off already made (see the architecture doc's Open Questions), not an oversight to "fix" here.
- **VALIDATE**: `npx prisma validate` passes.
- **SATISFIES**: TICKET-1 AC — "`QuizResponse` model defined."

### CREATE Supabase connection (needs the founder)

- **IMPLEMENT**: In the Supabase project dashboard → Project Settings → Database, copy the **Connection pooling** string (transaction mode, port 6543) into `.env` as `DATABASE_URL`, appending `?pgbouncer=true` if not already present; copy the **direct connection** string (port 5432) as `DIRECT_URL`.
- **GOTCHA**: This step requires real credentials only the founder has access to — it cannot be completed by the agent alone. Flagged in Open Questions/Assumptions below.
- **VALIDATE**: `npx prisma migrate dev --name init` completes without connection errors and creates the `QuizResponse` table (visible via `npx prisma studio` or the Supabase table editor).
- **SATISFIES**: TICKET-1 AC — "`npx prisma migrate dev` runs clean and creates the `QuizResponse` table."

### CREATE `lib/db.ts`

- **IMPLEMENT**: Standard Next.js Prisma singleton:
  ```ts
  import { PrismaClient } from "@prisma/client";

  const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };

  export const db = globalForPrisma.prisma ?? new PrismaClient();

  if (process.env.NODE_ENV !== "production") {
    globalForPrisma.prisma = db;
  }
  ```
- **PATTERN**: This is the pattern later tickets (TICKET-4's save-on-completion route) will import from — `import { db } from "@/lib/db"`.
- **GOTCHA**: Without the `globalThis` cache, every hot-reload in dev spins up a new `PrismaClient`, which can exhaust Supabase's pooled connection limit quickly.
- **VALIDATE**: A throwaway script or API route that calls `db.quizResponse.count()` returns `0` without throwing.
- **SATISFIES**: TICKET-1 AC — foundational for every future DB-touching ticket.

### CREATE `.env.example`

- **IMPLEMENT**: Mirror `.env`'s keys with placeholder values only:
  ```
  DATABASE_URL="postgresql://...pooled-connection-placeholder.../postgres?pgbouncer=true"
  DIRECT_URL="postgresql://...direct-connection-placeholder.../postgres"
  ```
- **GOTCHA**: Never put a real credential in this file — it's meant to be committed.
- **VALIDATE**: `git status` (once staged) shows `.env.example` staged and `.env` NOT staged.
- **SATISFIES**: Global CLAUDE.md security rule — `.env` gitignored before first commit.
